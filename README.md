# 웹소설 마케팅 레이더 (Webnovel Marketing Radar)

네이버 블로그·유튜브의 웹소설 관련 인기 콘텐츠를 **매시간 자동 수집**하고, 매일 아침 **07:10~07:40 KST 사이에 분석 브리핑을 이메일로 자동 발송**하는 시스템입니다. 승인 절차 없이 매일 무조건 발송됩니다.

- 발송 대상: `REPORT_TO` 시크릿에 등록한 주소 (예: fkssid0731@naver.com)
- 서버 불필요 — 문피아 모니터링과 동일하게 **GitHub Actions + 저장소 내 데이터 저장** 방식
- 리포트 구성: 오늘의 핵심 → 유튜브 → 네이버 블로그 → 인스타그램(수동 관찰) → 관심 작품 언급·홍보효과 프록시 → 오늘의 실행 제안(주간 플랜 + D-day 단계) → 인기 기준 자동조정 로그 + 상위 콘텐츠 CSV 첨부

```
┌ 매시 07분 ──────────────┐        ┌ 매일 KST 07:10 ─────────────────┐
│ collect.yml              │        │ daily-report.yml                 │
│  · 네이버 블로그 검색 API │  data/ │  · 24h/7일 집계·주제·형식·시간대 │
│  · 유튜브 통계 갱신(매시) │──────▶ │  · 도표 5종 생성(한글 폰트)       │
│  · 유튜브 신규 발굴(4회/일)│ state/ │  · 임계값 자동 조정               │
│  · 블로그 본문 표본 수집  │        │  · HTML 메일 + CSV 첨부 발송      │
└──────────────────────────┘        └──────────────────────────────────┘
```

## 1. 무엇을 측정하고, 무엇이 대리지표인가 (정직 고지)

| 항목 | 유튜브 | 네이버 블로그 | 인스타그램 |
|---|---|---|---|
| 주제·형식·업로드 시각/요일 | ✅ 직접 측정 | ✅ 주제 / △ 형식·시각은 본문 표본에서 판별 | ✋ 수동 관찰 |
| "접속자가 늘어나는 시간" | △ **조회수 증가 속도**(매시 스냅샷 차분)로 근사 | ❌ 조회수 비공개 → 검색노출·공감으로 대체 | ✋ 수동 |
| 접속자 반응 | ✅ 좋아요·댓글 수 + 베스트 댓글 샘플 | △ 공감 수(베스트에포트) | ✋ 수동 |
| 홍보효과 | △ 관심작품 **언급량 ↔ 문피아 순위** 동반 변화(상관 관찰, 인과 단정 불가) | 동일 | — |

- 타인 채널·블로그의 실제 방문자 통계는 외부에서 절대 볼 수 없습니다. 본 시스템은 **공개 지표의 시간대별 변화**로 이를 근사합니다.
- 인스타그램은 공식 API가 비즈니스 계정 + Meta 앱 검수 + 해시태그 30개/주 한도 등 제약이 커서 v1에서는 자동화하지 않습니다. `manual/instagram_notes.md`에 관찰 메모를 적으면 다음 날 브리핑에 그대로 실립니다. (원하면 이후 Meta Graph API 연동 버전으로 확장 가능)

## 2. 설치 절차 (약 30~40분, 순서대로)

### ① 네이버 검색 API 키 발급 (무료, 일 25,000회)
1. https://developers.naver.com → 로그인 → **Application → 애플리케이션 등록**
2. 애플리케이션 이름: `webnovel-radar` / 사용 API: **검색** 체크
3. 환경: **WEB 설정**, 웹 서비스 URL에 `https://github.com` 입력(형식용)
4. 발급된 **Client ID / Client Secret** 두 값을 메모

### ② 유튜브 API 키 발급 (무료, 일 10,000유닛)
1. https://console.cloud.google.com → 새 프로젝트(예: webnovel-radar)
2. **API 및 서비스 → 라이브러리 → "YouTube Data API v3" → 사용 설정**
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키** → 키 메모
4. (권장) 키 제한: API 제한 → YouTube Data API v3만 허용

### ③ Gmail 앱 비밀번호
- 문피아 리포트에 쓰던 **기존 앱 비밀번호를 그대로 재사용**하면 됩니다.
- 새로 만들 경우: Google 계정 → 보안 → 2단계 인증 켬 → **앱 비밀번호** 생성(16자리)

### ④ GitHub 새 저장소 생성
- 이름 예: `webnovel-radar`
- **Public / Private 선택 기준(중요)**
  - Public: Actions 무료 무제한 → 매시 수집 그대로 사용. 수집 데이터(공개 콘텐츠 메타데이터)와 config의 작품명·키워드가 공개됨.
  - Private: 무료 계정은 월 2,000분 한도. 본 시스템은 월 약 1,300~1,600분 사용 → **문피아 매시 파이프라인과 같은 계정에서 병행 시 한도 초과 가능**. 이 경우 `collect.yml`의 cron을 `"7 */2 * * *"`(2시간 간격)로 바꾸면 절반으로 줄어듭니다. (시간대 분석 해상도는 약간 떨어지지만 충분히 동작)

### ⑤ 파일 업로드
- 이 폴더의 전체 내용을 저장소에 업로드합니다.
- 웹 UI 업로드 시 `.github/workflows/` 숨김 폴더는 드래그가 안 되므로, 문피아 때처럼 **Add file → Create new file** 에서 파일명 칸에 `.github/workflows/collect.yml` 을 직접 입력해 내용을 붙여넣는 방식으로 두 워크플로를 만듭니다.

### ⑥ Secrets 등록
저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 아래를 등록:

| 이름 | 값 |
|---|---|
| `NAVER_CLIENT_ID` | ①의 Client ID |
| `NAVER_CLIENT_SECRET` | ①의 Client Secret |
| `YOUTUBE_API_KEY` | ②의 API 키 |
| `GMAIL_ADDRESS` | 발신용 Gmail 주소 |
| `GMAIL_APP_PASSWORD` | ③의 16자리 앱 비밀번호 |
| `REPORT_TO` | `fkssid0731@naver.com` |
| `MUNPIA_JSON_URL` | (선택) §4 문피아 연동 참조 |
| `MUNPIA_TOKEN` | (선택) 문피아 저장소가 Private일 때 PAT |

### ⑦ 첫 실행·검증
1. **Actions 탭 → "I understand… enable them" 클릭**(비활성 상태인 경우)
2. `collect` 워크플로 → **Run workflow** 수동 실행 → 초록 체크 확인 (data/ 폴더에 오늘 날짜 파일 생성됨)
3. `daily-report` 워크플로 → **Run workflow** 수동 실행 → 몇 분 내 메일 수신 확인
4. 메일이 안 보이면 **네이버 메일 스팸함** 확인 후 "스팸 아님" 처리 (첫 수신 시 종종 분류됨)

### ⑧ 완료
- 이후 자동: 매시 7분 수집 / 매일 KST 07:10 리포트 발송(도착 통상 07:15~07:40).
- 첫 1~2일은 표본이 얕아 "축적 중" 표시가 섞입니다. **시간대·요일 분석은 1주 후, 반응 속도 분석은 스냅샷 30쌍 이상부터** 신뢰 구간에 들어갑니다.

## 3. 리포트가 매일 하는 일

1. **인기 기준 자동조정** — 발굴 풀이 목표(유튜브 12~45편, 블로그 12~35명)를 벗어나면 기준을 ×1.4 / ÷1.4로 강화·완화하고, 조정 내역을 리포트 하단에 기록합니다. (`state/thresholds.json`)
2. **주제 8분류** — 예고편·티저 / 명대사·명장면 / 캐릭터·세계관 / 작가 후기·창작기 / 리뷰·감상 / 추천·큐레이션 / 플랫폼·시장 동향 / 미디어믹스
3. **형식 분류** — 유튜브: 쇼츠·숏폼·롱폼(재생시간 기반) / 블로그: 카드뉴스형·혼합·텍스트(본문 이미지 수 기반, 표본)
4. **시간대 분석** — 업로드 시각 분포 + 유튜브 조회수 증가 속도의 시간대 프로파일 → 상위 2개 시간대 적색 강조
5. **실행 제안** — 위 데이터로 "채널별 주당 횟수·콘텐츠·형식·권장 시간대" 표를 매일 갱신 + 10/7 런칭 D-day 단계별 할 일
6. **첨부** — 당일 상위 콘텐츠 CSV(엑셀에서 바로 열림)

## 4. (선택) 문피아 모니터링 연동 — "홍보효과" 열 활성화

기존 문피아 저장소가 상위 50위 데이터를 JSON으로 저장 중이라면:

1. 해당 JSON 파일의 **Raw URL**을 복사 (예: `https://raw.githubusercontent.com/<계정>/<저장소>/main/data/latest.json`)
2. 이 저장소 Secrets에 `MUNPIA_JSON_URL` 로 등록. 문피아 저장소가 Private이면 GitHub **PAT(repo 읽기 권한)** 를 만들어 `MUNPIA_TOKEN` 에 함께 등록
3. JSON이 `[{"title": "...", "rank": 1}, ...]` 형태(키 이름에 title/제목, rank/순위가 포함되면 자동 인식)면 리포트의 "관심 작품" 표에 문피아 순위가 붙습니다.

이후 콘텐츠 언급량과 순위의 동반 변화를 매일 눈으로 추적할 수 있습니다.

## 5. 운영·조정

- **키워드/관심작품 변경**: `config.json`의 `keywords`, `watch_titles` 수정 후 커밋 — 즉시 반영. 경쟁작·유사 장르 작품을 watch_titles에 넣을수록 홍보효과 관찰이 정교해집니다.
- **발굴 시각 변경**: `youtube.discovery_hours_kst` (기본 8·13·19·23시, 하루 4회 — 유튜브 쿼터의 대부분을 여기서 사용)
- **인스타그램 메모**: `manual/instagram_notes.md`를 웹에서 바로 편집(연필 아이콘) → 다음 날 브리핑에 반영
- **발송 시각 변경**: `daily-report.yml`의 cron(UTC 기준, KST−9시간). GitHub 사정으로 수 분~수십 분 지연될 수 있어 07:10 시작으로 8시 이전 도착을 노립니다.

## 6. 문제 해결

| 증상 | 조치 |
|---|---|
| 메일이 안 옴 | 네이버 스팸함 확인 → Actions의 daily-report 로그에서 `발송 실패` 여부 확인 → GMAIL 시크릿 오타 확인 |
| collect가 빨간불 | 로그에서 어느 API 단계인지 확인. 키 오타/미활성화가 대부분. 개별 API 실패는 건너뛰고 계속 수집하도록 설계됨 |
| 60일 뒤 자동 중지 경고 | GitHub는 저장소 활동이 없으면 예약 워크플로를 중지하지만, 본 시스템은 매시 데이터를 커밋하므로 해당 없음 |
| Private 한도 초과 | `collect.yml` cron을 `"7 */2 * * *"` 로 변경 |
| 유튜브 쿼터 초과(403) | `discovery_hours_kst`를 2회로 줄이거나 `search_results_per_keyword`를 15로 하향 |

## 7. 폴더 구조

```
config.json                  ← 모든 설정(키워드·작품·임계값 기본치)
scripts/collect.py           ← 매시 수집기
scripts/daily_report.py      ← 일일 분석·발송기
scripts/common.py            ← 공용 로직(분류기·임계값)
scripts/make_sample_data.py  ← 테스트용 합성 데이터(실서비스 미사용)
.github/workflows/           ← 자동 실행 스케줄 2종
manual/instagram_notes.md    ← 인스타 수동 관찰 노트
data/YYYYMMDD/*.jsonl        ← 수집 원본(자동 생성)
state/*.json                 ← 추적 목록·임계값·로그(자동 생성)
```
